## هدف

یک مرجع واحد برای «شروط تست» در k6: چه چیزی را validate کنیم (Checks)، چه چیزی را
pass/fail کنیم (Thresholds) و چطور تفکیک و تحلیل کنیم (Tags).

## سه لایه در یک نگاه

| لایه | نقش | اثر بر نتیجه |
|---|---|---|
| Check | assertion نقطهای روی هر پاسخ | فقط آمار (برای fail شدن نیاز به آستانه دارد) |
| Threshold | معیار pass/fail کل تست | exit code 99 در صورت نقض |
| Tag | تفکیک/فیلتر | آستانهٔ per-endpoint/flow/... |

## قوانین طلایی تیم (الزامی)

1. **Sample Guard اجباری**: هیچ آستانه‌ای بدون گارد (`http_reqs count>0`) — و برای
   خانوادهٔ Checkها `assert_total{tag} count>0` — نوشته نشود.
2. **تگ‌گذاری استاندارد**: فقط کلیدهای `shared/tags.js`؛ کاردینالیتی پایین؛ بدون شناسهٔ یکتا.
3. **فیلتر تگ فقط تطبیق دقیق**: Regex در آستانه کار نمیکند (تلهٔ شماره ۳ در بخش تلهها).
4. **اعداد فقط از `config/slo.js`** با قابلیت override با `-e SLO_...`.
5. **aggregationها را رعایت کنید**: Rate فقط `rate`، Gauge فقط `value`،
   Trend فقط `avg,min,max,med,p(N)`، Counter فقط `count,rate`.

## چکلیست شروط تست (گیت هر سناریو)

- [ ] Error Budget تعریف شده؟ (`http_req_failed rate<...`)
- [ ] بودجهٔ تأخیر با percentile (نه فقط avg)؟ (`p(95)`, `p(99)`, `max`)
- [ ] نرخ موفقیت Check بسته شده؟ (`checks rate>...`)
- [ ] گارد اشباع هست؟ (`dropped_iterations count==0`)
- [ ] تگهای endpoint/flow روی درخواستها و Checkها ست شده؟
- [ ] Sample Guard برای هر آستانهٔ تگدار وجود دارد؟
- [ ] برای تراکنشهای کسبوکار، SLA تگدار تعریف شده؟
- [ ] در تستهای منفی از `expectedStatuses` استفاده شده؟
